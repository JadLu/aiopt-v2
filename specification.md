# POLARIS SM — Product Specification

## 1. Product

POLARIS SM is a web app that helps e-commerce sellers in the Middle East and North Africa (MENA) test and launch a product. For each product the user creates a project, and the app produces:

1. **A marketing plan** written for the chosen market(s): audience, channels, content themes, campaign phases, KPIs and a 30-day action plan.
2. **Creatives** based on that plan: AI images, AI videos with a timeline editor, and AI-written landing pages.
3. **A product brief** that can be pre-filled from a shop link (AliExpress, Amazon, Shopify and similar).

**Users:** MENA e-commerce entrepreneurs who test products quickly, and marketers who run several products or clients.

**Languages:** Arabic (RTL), English and French. Arabic dialect is derived from the target market.

## 2. Features

### Accounts
- Email/password and Google sign-in (Firebase Authentication).
- Each user's data is private to them (`users/{uid}`).
- Settings: display name, theme (light / dark / system), password reset, sign out, account deletion.

### Projects
- Create a project with: product name, description (up to 500 characters), one or more target markets, and an optional product photo.
- Import from a link: paste a product page URL and the name, description and photo are pre-filled for the user to check. Free; 10 imports per 10 minutes.
- Multiple target markets are supported (ISO country codes, grouped by region, with the Arabic dialect shown for MENA groups).
- Project list with status filter, search and counts; project cards and rows; dashboard with KPIs and the project grid.
- Project page with a four-step flow: **Brief → Plan → Creatives → Library**, each with a live status, and a **Switch project** menu in the header to jump to another project.

### Marketing plan
- Generated by the AI (KIE AI, `gpt-5-5`) and streamed into the app. Sections appear as they finish; the user can leave the page while it runs.
- Six sections, shown as visual components: Market analysis, Channels, Content, Phases, KPIs, Action plan.
- **Angles:** the plan proposes several audience angles. The user can star one, regenerate a single angle, and choose "Use this angle", which pre-selects it in Creatives. Regenerating an angle costs 5 credits.

### Creatives
- **Images:** text-to-image via KIE AI (`nano-banana-2`), aspect ratios 1:1, 4:5 and 9:16, resolutions 1K / 2K / 4K.
- **Videos:** text- and image-to-video via KIE AI (`gemini-omni-video`), aspect ratios 9:16, 16:9 and 1:1, durations 5 / 8 / 10 s, resolutions 480p / 720p / 1080p.
- **Video editor:** a timeline for assembling clips (with hook and body markers) and exporting a final render. Clips are not saved between sessions.
- **Landing pages:** full HTML landing pages via KIE AI Claude (`claude-opus-4-7`), using a copywriting framework (AIDA, PAS or FAP) and optional segment, pillar and hook from the chosen angle. Preview, download as HTML, and export as an image.
- **Library:** every finished image, video and landing page for a project, with download and delete.
- Generation is asynchronous: the server returns a task ID and the app polls until the result is ready.

### Credits and notifications
- Credits are the usage currency. Costs: marketing plan 20, image 35, landing page 35, angle regeneration 5, video 240 (≤6 s), 260 (8 s) or 300 (10 s+).
- Failed generations are refunded automatically, exactly once.
- Insufficient credits open a dialog with the price list; the browser never changes a balance.
- In-app notifications: plan ready, creatives ready, generation failed (with refund), credits low (once a day). Shown by a bell in the header and a Notifications page.

## 3. Data model

```
users/{uid}                              ← credits (number, server-written, read-only for clients)
  /projects/{projectId}                  ← name, description, country(ies), status, marketing plan, angles, productImageUrl
    /ai-creatives/{id}                   ← AI images (status: pending | done | failed)
    /ai-videos/{id}                      ← AI videos (status: pending | done | failed)
    /rendered-videos/{id}                ← final video exports
    /ai-landing-pages/{id}               ← landing pages (status: pending | done | failed; html)
  /jobs/{taskId}                         ← server-written generation jobs (read-only for clients)
  /notifications/{id}                    ← server-written notifications (client: read, mark read, delete)
rateLimits/{uid}_{bucket}                ← server-only rate-limit counters
```

Clients can read and write their own `projects` subtree. Everything else is server-only.

## 4. External services

| Variable | Side | Purpose |
|---|---|---|
| `KIE_AI_API_KEY` | server | All AI generation (plan, images, videos, landing pages) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | server | Firebase Admin SDK (token checks, credits, jobs, notifications) |
| `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` | both | Cloudinary account for uploads and hosted media |
| `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | server | Signed uploads |

Firebase client configuration is public and hardcoded in `lib/firebase/config.ts`.

### KIE AI models

| Model | Used for |
|---|---|
| `gpt-5-5` (SSE stream) | Marketing plan and angle regeneration |
| `nano-banana-2` | Images |
| `gemini-omni-video` | Videos |
| `claude-opus-4-7` (SSE stream) | Landing pages |

## 5. Hosting

- Next.js (App Router) on Vercel. Server routes run on Node.js.
- Firestore rules are deployed from `firestore.rules`; they must be redeployed after any change.

## 6. Conventions

- Firebase client modules are client-side only and use lazy getters.
- Auth state comes from `useAuth()` only.
- Every API route validates its input with zod (`lib/validation.ts`) and checks auth and rate limits first.
- Credits change only on the server (`lib/firebase/admin-credits.ts`).
- Styling uses design tokens in `app/globals.css` (see `docs/redesign/DESIGN.md`).
